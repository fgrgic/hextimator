# Multi-tenant and SSR

The primary integration path for white-label and per-tenant branding is **server-side**: resolve the tenant from the request, generate CSS once per HTML payload (or from cache), and send variables before paint.

No React runtime is required. No browser hooks.

## Route-level SSR

Resolve `tenant.brandColor`, generate stylesheet text, and inline or link it:

```ts
import { hextimate } from "hextimator";

app.get("/*", async (req, res) => {
  const tenant = await loadTenant(req);
  const css = hextimate(tenant.brandColor).format({ as: "css" });
  const html = renderApp({ tenant });
  res.send(`<!DOCTYPE html><html><head><style>${css}</style></head><body>${html}</body></html>`);
});
```

Use `.preset()`, `.style()`, and `.format()` options the same way as in the browser ([Customization](./customization.md), [Presets](./presets.md)).

## React layout (SSR-safe)

If you already render HTML with React on the server, [`HextimatorStyle`](./react.md) emits a `<style>` element during render (no `useEffect`). Drop it in your root layout `<head>`:

```tsx
import { HextimatorStyle } from "hextimator/react";

export function RootLayout({ tenant }: { tenant: { brandColor: string } }) {
  return (
    <html lang="en">
      <head>
        <HextimatorStyle color={tenant.brandColor} />
      </head>
      <body>{/* ... */}</body>
    </html>
  );
}
```

Pass **`presets`**, **`style`**, **`format`**, and **`darkMode`** props when you need presets or a specific dark-mode strategy ([React](./react.md)).

## Caching

- **Static tenants**: build CSS at deploy time or bake tokens into config.
- **Dynamic tenants**: cache `{ tenantId, color, presetRevision } → css string` in memory or Redis; invalidate when branding changes.

Contrast guarantees apply to **opaque pairs** generated by hextimator. If your shell renders tenant CSS over unpredictable photographic backgrounds, validate separately.

See also [Performance](./performance.md) for typical generation latency.
